# 去向、生命周期与更新层级

> 路由是判断结果，不是四种必须生成的文件模板。遵循实际目标项目的 `AGENTS.md`、目录权限和人的决定；不把本仓库的研究笔记结构强加给其他仓库。

## 四种合法去向

1. **只讨论，不落盘：**短咨询、无后续意义、价值不明或安全与权限不足时，回答原问题，明确未持久化；不造空笔记。
2. **新专题：**原问题有独立、可回查的目标，且有权者选定位置和允许创建；从当前问题、范围、未决与证据开始，不自动把所有聊天搬进去。
3. **既有专题的新里程碑：**问题可独立验收、可终止，且已有专题对它适用并获授权；先记录为何与旧目标不同，编号不因失败回收。
4. **维护既有：**新证据／纠偏属于已有问题时，在获授权的过程篇按实际顺序追加，并跟进同层当前摘要；目标状态、跨目标关系或导航实变且获授权时才更新根总览。已冻结判断被反证时，保留旧判断、人的确认范围与形成原因，显著交叉指向新证据或新目标；不能静默改写历史。

## 三层阅读职责，不是三套强制目录

| 视图 | 读者要找到什么 | 常见承载与更新条件 |
| --- | --- | --- |
| 微观 micro | 某个独立问题的证据、尝试、决定与纠偏怎样按时序形成 | 已授权的问题过程篇或既有文档内的过程节；不把每轮聊天变成一篇。 |
| 中观 meso | 单目标目前的判断、适用范围、验证边界、最新进展与证据入口 | 已授权的目标摘要；若目标采用过程篇／摘要结构，每次过程篇变更都跟进摘要的**进展或入口**，结论／边界只在意义实变时修改。 |
| 宏观 macro | 已启动目标、未启动候选、当前效力、跨目标关系和导航 | 已授权的专题地图；目标状态／关系／导航实变才更新，不逐次抄录过程。同一文件的不同节也可承载这些职责。 |

1. **适配现有结构：**原问题可独立确认或终止且有权者确认边界时，才考虑新里程碑；同一目标的不同方法先放在同一目标。采用编号的项目把未启动方向留为未编号候选、启动后才取不复用的编号，失败不回收；不是一见“macro”就自建 Vault 或重排旧文件。
2. **向上概括而非复制：**摘要与地图引用当前可访问、可安全引用的依据，分清历史确认与当前效力；缺乏证据写未验证。不强制先造 micro 文件才能写 meso：现有可靠来源也可供目标摘要引用；安全和位置不足时不写。规划里程碑完成不代表三层正文、新目录或冻结均获批准。
3. **不完整权限时：**过程篇、目标摘要、专题地图的写入权分别核查；无权改上层时报告未同步的范围，不声称地图最新。若目标项目要求过程与摘要同一逻辑变更同步且无法获权，就暂缓依赖同步的写入，不用收件箱绕过规定。

## 写入前的定位关口

- 先读目标项目的约定，确定作者或有权者及已授权的专题／路径；同名或相似目标不可仅凭语义匹配就改旧稿。
- 首次没有获授权目标时，先完成可独立回答的原问题；有记录价值时再请有权者在现有 Vault 或普通文档目录中选择和授权。只有原任务本身被位置选择阻断时才先问；暂不选择就报告未持久化，不自建默认目录。
- 唯一获授权目标存在但“属于哪篇”待确认时，可再查看 [safe-inbox](safe-inbox.md) 的严格条件；多个候选目标不构成唯一目标。
- 对每次新文件、修改、搬移、提交明确操作授权。决定**写入**不自动允许 Git 提交、公开 push 或宿主自动安装。

## 冻结与有效性

“已冻结”只来自人的明确确认，必须注明冻结的是哪些决定和哪些未决；不意味着永远适用、AI 的每条提案获批或真实效果已验证。独立探索终止须保留失败原因与可复验部分，**不同于**曾冻结的成果后来失效；后者保留旧正文与确认史，在获授权的旧摘要显著提示当前失效并链接新依据，新结论待人确认，必要时更新已授权的宏观状态。敏感旧材料遵从安全例外，不机械原样保留。标记草案、当前共识、过程记录的状态时不要混同三者。任务结束时，回答原目标并说明实际写入／未写入范围。
