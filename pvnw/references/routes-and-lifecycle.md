# 去向、生命周期与更新层级

> 路由是判断结果，不是四种必须生成的文件模板。遵循实际目标项目的 `AGENTS.md`、目录权限和人的决定；不把本仓库的研究笔记结构强加给其他仓库。项目级目录／命名、WBS、生命周期与同步批次的权威合同在 [project-system](project-system.md)；本篇负责四路由及建系／旧库重构的执行分支。

## 四种合法去向

1. **只讨论，不落盘：**短咨询、无后续意义、价值不明或安全与权限不足时，回答原问题，明确未持久化；不造空笔记。
2. **新专题／从零建系：**原问题有独立、可回查的目标，且有权者选定位置与创建范围；若要求完整项目文档体系，按下方「空白建系」交付可走通的宏观→中观→微观结构，而非只讨论三层名词。暂无真实已启动目标时不伪造编号、空目标摘要或过程篇。
3. **既有专题的新里程碑：**问题可独立验收、可终止，且已有专题对它适用并获授权；先记录为何与旧目标不同，编号不因失败回收。
4. **维护既有／受控重构：**新证据／纠偏属于已有问题时，在获授权的工作包篇按实际顺序追加，并跟进同层当前摘要；项目范围／全局风险或待决策、目标状态／跨目标关系或导航实变且获授权时才更新根总览。若委托重构整套旧结构，须先只读盘点、映射、评估链接／人工编辑，再按单项许可分批执行下方「旧库重构」；不能把跨目标搬移当普通增量更新。已冻结判断被反证时，保留旧判断、人的确认范围与形成原因，显著交叉指向新证据或新目标；不能静默改写历史。

## 两种结构级分支：授权后执行，不增加第五路由

### 空白建系（路由 2 内）

1. 先确认原项目问题、一个可观察的建系出口、目标路径及允许新建的**具体**根、子目录和文件。只读核查项目约定、路径碰撞、已有授权 Vault 是否可用；有 Obsidian 客户端却无获授权 Vault 不等于能擅建 `.obsidian`／安装插件。有权者选定的唯一授权 Vault **或**普通 Markdown 目录都是有效目标；没有选定目标时请其决定，不因另有可用 Vault 就覆盖其已选普通目录。两种承载都以 `.md` 和相对 Markdown 链接为基线，无 Git／插件依赖。
2. 以真实目标组织文档，而不是从流程模板反推虚构目标。授权完整结构且首个独立、可终止目标边界已经由有权者确认时，可采用 `0_项目总览.md` → `1_目标/1.0_当前判断.md` → `1_目标/1.1_工作包.md` 或可直接引用的安全依据；编号不预占、不复用，已有项目的命名约定优先。工作包有管理价值且获权时，以 `1.1` 文件为**工作包及其完整过程的唯一身份**，摘要只维护其状态／依赖／入口，不另造 `1.W1`；见 [project-system](project-system.md)。**即使目前只有一个目标**，明确建系且根导航获权时也要提供项目／专题起点与到当前目标的入口，而不是因暂无跨目标关系就略过宏观。根记录已启动目标、未编号候选、状态／依赖与入口；摘要记录目标出口、当前阶段、下一节点及证据入口。已经提供安全、获权且属于可追踪工作包的过程材料时，须在相应 `N.1…` 工作包篇内用清单体写原问题、原始安全条目、来源、尝试与纠偏，并从 `N.0` 链接；仅有可安全访问的既有依据而无工作包过程时可直链该依据，不伪造过程或空工作包。如果目标还只是候选，可在获权范围设计／创建有实际用途的根导航，**不**造空编号、空摘要／工作包篇，更不声称已形成三层证据链。
3. 用实际授权范围验证宏根→中目标摘要→micro 工作包篇**或安全、可读的既有依据**的逐级跳转与反向入口。已获全套权限、已有工作包过程材料却漏 micro 篇／节（或已有依据链接）时，不能宣称完整建系；证据、目标边界或任一层权限缺失时仅交付合法的部分并报告链路**未闭合**及下一步，绝不拿空模板补齐。核验生成文件的相对链接和碰撞，若有 WBS 还逐跳核工作项→证据或标缺口；回答原建系问题时报告实际目录及未建项。只新增导航也可能半途失败：停止后续写入，列残留与失效链接；没有逆操作／删除许可不清理，见 [project-system](project-system.md) 的批次收尾。仅为口头咨询或一次性任务，不造此结构。

### 旧库重构（路由 4 内；若确认是新独立目标可另走路由 3）

1. **先只读：**盘点原文件、作者规则／人的编辑、历史确认、当前索引、文件间相对链接／锚与附件、跨目录引用及敏感／公开边界；确认可用的恢复手段（有 Git 可用但**不要求**安装），不能假设“有备份”或 `.gitignore` 足以复原。
2. **先出差异与停机条件：**列旧路径／入口→拟建宏／中／微路径／对应节、哪些只新增索引、哪些拟复制／改名／移动／删除、冲突、断链或证据失效风险；把**只新增链接索引**作为较低风险的起点。未确认所有权、范围、链接和回退方式前不做破坏性搬移；仅有读取或方案授权就只给方案。
3. **分批执行与回滚：**逐项获准创建、修改、移动、删除、备份存放范围和**失败时逆操作**。每批动旧文件前明确已获准、实存且可验证的恢复点（旧入口或安全快照）、旧→新清单及允许的回退步骤；没有可用恢复点／恢复权限，不做破坏性移动、覆盖或删除，仅出方案或获权加索引。小批次更新双向链接与附件引用后，实际检查根→目标→过程／依据、旧入口与人的确认史；失败时先停止后续批次，按已获权步骤**回滚本批变更**，重查旧入口、附件、锚及新的残留链接，报告恢复结果和仍未复原的部分。回滚本身权限不足时不擅修他人资料，立即停机并列出具体人工恢复清单；不能声称迁移成功。需要公开或 Git 仍另行许可。

## 三层阅读职责，不是三套强制目录

| 视图 | 读者要找到什么 | 常见承载与更新条件 |
| --- | --- | --- |
| 微观 micro | 某个 WBS 工作包的交付与依赖、整段执行过程、原问题／安全来源、尝试、决定、反证和纠偏怎样按先后形成 | 已授权的 `N.1_<name>.md` 等工作包篇；同包多轮留在同篇，按 [note-modeling](note-modeling.md) 的 Markdown 清单体写作；现有等价入口优先。 |
| 中观 meso | 独立目标的出口、当前阶段、下一评估节点、工作包索引／依赖、预期与实际证据／反证及下一步 | 已授权的 `N_<name>/N.0_<name>.md` 或等价摘要；若目标采用 micro→摘要结构，每次工作包篇变更都跟进摘要的**进展或入口**，结论／边界只在意义实变时修改。 |
| 宏观 macro | 已启动目标、未启动候选、当前效力、跨目标关系和导航 | 已授权的专题地图；项目范围／全局风险或待决策、目标状态／关系／导航实变才更新，不逐次抄录过程。同一文件的不同节也可承载这些职责。 |

1. **适配现有结构：**原问题可独立确认或终止且有权者确认边界时，才考虑新里程碑；同一目标的不同方法先放在同一目标。采用编号的项目把未启动方向留为未编号候选、启动后才取不复用的编号，失败不回收；不是一见“macro”就自建 Vault 或重排旧文件。
2. **向上概括而非复制：**摘要与地图引用当前可访问、可安全引用的依据，分清历史确认与当前效力；缺乏证据写未验证。不强制先造 micro 文件才能写 meso：现有可靠来源也可供目标摘要引用；安全和位置不足时不写。规划里程碑完成不代表三层正文、新目录或冻结均获批准。
3. **不完整权限时：**过程篇、目标摘要、专题地图的写入权分别核查；无权改上层时报告未同步的范围，不声称地图最新。写前先预检本轮过程、摘要、WBS 及根所需权限；若目标项目要求过程与摘要同一逻辑变更同步且无法获权，就暂缓依赖同步的写入，不用收件箱绕过规定。
4. **逐级披露的验收：**从宏观当前状态和依赖点击到中观目标与阶段，再到微观支持特定判断的原问题／证据、反证或可安全访问的外部依据；微观返回目标，中观返回根。核对相对路径、锚、附件在**拟提交或实际交付的文件集合**中有效。即使同文不同节承担职责，也要给可定位的节入口；没有证据标缺口，不把“文件存在”当可回查。

## 可评估节点与目标演化

1. 一个**节点**是可判断是否通过的关键门槛，围绕它探索的目标可跨多次任务和多种方法。提出下一节点时问：跳过会漏掉什么必要判断、前置依赖是否成立、什么安全可观察交付物能检验、失败会怎样停／改？不能把耗时活动、每轮聊天、目录或阶段标签直接当里程碑号。独立可确认或终止的新目标边界由有权者确认；未启动候选不占号，已分配号码即使失败也不复用。
2. 在目标摘要记录目标出口、当前阶段、下一节点的预期证据／失败信号、已有实测／反证、未验证与行动者下一步；允许从**原点假设、从目标倒拆依赖、正推小检验、风险／失败时复盘**中选合适组合。这些是用户提供课程整理材料启发的**可检验规划方法**，并非已独立核验的课程原文或必填量表；“先宏观再微观”是设计阅读导航的启发，不阻止先收集证据或先答原问题。
3. 节点达到、重大风险、失败或大量回退时复评是否继续、纠偏、暂停或终止：记录原判据、实际证据与代价、变更理由及下一低成本验证；必要时提出新独立目标并由有权者确认。摘要**进展／入口**随过程增量跟进，判断与边界只在证据实变时调整，根只在项目范围／全局风险或待决策、目标状态／关系／导航实变且有权时改；节点测试通过**不自动冻结**，冻结需人的明确确认与范围。

## 写入前的定位关口

1. 先读目标项目的约定，确定作者或有权者及已授权的专题／路径；同名或相似目标不可仅凭语义匹配就改旧稿。
2. 首次没有获授权目标时，先完成可独立回答的原问题；有记录价值时再请有权者在现有 Vault 或普通文档目录中选择和授权。只有原任务本身被位置选择阻断时才先问；暂不选择就报告未持久化，不自建默认目录。
3. 唯一获授权目标存在但“属于哪篇”待确认时，可再查看 [safe-inbox](safe-inbox.md) 的严格条件；多个候选目标不构成唯一目标。
4. 对每次新文件、修改、搬移、提交明确操作授权。决定**写入**不自动允许 Git 提交、公开 push 或宿主自动安装。

## 冻结与有效性

1. **冻结：**只能来自人的明确确认，标明确认范围与未决；不代表永远适用、AI 提案均获批或效果已验证。
2. **终止与失效：**独立探索终止须保留失败原因及可复验点，**不同于**曾冻结成果后来失效；后者保留旧确认史，在获权的摘要标新反证和当前待确认，必要时更新获权宏状态。
3. **安全与出口：**敏感历史服从安全例外；草案、当前共识与过程记录不混同。结束时回答原目标和实际写入／未写入范围。
