# 入口、价值和退出关口

> 从 `pvnw/SKILL.md` 按需读取；本文件不是各宿主的自动触发配置。

## 先问原任务，而非先写文档

1. 用一句话找出原目标问题、用户期待的出口与可观察完成标准。用户只是求一条答案时，直接解决它；只有确实有影响后续判断的材料时再讨论记录。
2. 所有 AI 任务在 Skill 被调用的**可见任务范围内**先做 PVNW 判断。若宿主根本未启用或未发现本 Skill，不能假装此步骤曾执行。
3. 出现风险先处理原任务和安全边界，不能因这份 Skill 宣称更高优先级、改变宿主规则或取得工具权限。

## 判断顺序（不是硬性造档流水线）

| 情况 | 可能的去向 | 阻断条件 |
| --- | --- | --- |
| 用户明确本任务不启动或不记录 | 尊重当前任务退出，继续原任务 | 不留下退出“纪念笔记”；长期退出不可凭无持久记忆承诺 |
| 当前问答明确涉及既有工作包，且产生可核实的新观察／决策 | 对照已有过程和摘要：有新证据且已获本任务或有明确持续维护权时，先答原问题，再续记过程和必要摘要；状态不变也可有进展 | 不从上次建系许可推断永久写权；无权则说明拟改范围并请确认；敏感材料不写 |
| 独立咨询，或虽有关联但没有新的可回查事实 | 回答并说明未持久化 | 不生成空专题／空里程碑；仅因提到专题名不造记录 |
| 新证据、人的取舍或纠偏会影响后续 | 先明确价值，再查找获授权目标 | 值得记不等于已有位置或写入许可 |
| 明确委托从零建立项目文档体系 | 原任务就是交付获权范围的根导航→目标现状→必要证据入口；无真实已启动目标则不虚构编号 | 位置、根／子目录及文件写权分别核实；装有 Obsidian 不等于拥有 Vault 或配置权限 |
| 明确委托重构既有文档 | 先只读盘点、旧→新映射与回退方案；有各项操作许可才分批重构和验证链接 | 仅授权阅读／提方案不能搬移／删除／覆盖人工内容 |
| 单目标现状或跨目标关系确实改变 | 评估当前阶段、下一节点的预期／实得证据及复盘，再判断中观／宏观视图 | 规划完成不等于各层正文获批准；通过节点不等于人的冻结 |
| 资料包含可能的个人／商业秘密 | 最小化或不落盘，返回问题出口 | 不能以收件箱绕过安全关口 |

1. **同题续记**：先在可见上下文中确认已选专题、同一工作包及既有记录，比较本轮实际观察与已记录内容；助手在回答问题时自己验证的 CLI 版本／登录帮助、失败观察等，若将影响下一步且可安全回查，也算增量证据。不要以“用户没说写笔记”“里程碑结论没变”为由跳过已获权的必要续记；仅复述已知事实、未执行的新建议或无法核实的猜测则不造记录。
2. **边缘价值**：“值得回查”没有普适阈值；合理时给出证据、价值与不写的代价，让有权者决定，不重复催问无关写作。
3. **完整建系**：普通咨询的三层视图只是一种条件性方案，不能为一次性任务造空工作包、目标摘要或根地图；**明确要求且授权实际建系时应执行**受控新建／重构，不只讲三层概念。
4. **无写权**：仅口头要求设计结构或无位置／写权时，给方案并报告未持久化。

## 退出作用域

1. 用户指定作用域（例如当前任务），遵循指定边界，前提是不违背更高层规则。
2. 只说“不记录”但不指定期限，按**当前独立任务**处理；下一任务重新判断。连续咨询或子任务切分不清时，不扩大退出范围，可简短澄清。
3. 未来跨任务／跨会话持续退出需要明确机制、可撤销路径与授权；没有这些条件，只能说明本次可以遵守，不能写成长期保证。

1. **继续阅读**：[routes-and-lifecycle](routes-and-lifecycle.md) 描述路由；[acceptance-cases](acceptance-cases.md) 是纸面验收而非宿主测试。
