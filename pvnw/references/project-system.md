# 项目管理合同：命名、WBS、更新与生命周期

> 按需读取：明确获权建项目文档体系、分解或追踪里程碑／WBS、维护过程、改名或迁移时。日常独立问答只按 [decision-gates](decision-gates.md) 判断价值，不因此默认创建项目。此处是**新建时的可移植基线**，目标项目已有命名／ID／计划工具、人的决定和宿主约束优先；不得并行造第二套冲突账本。只读讨论无写权时给方案，不建目录。

## 一张对象表，三层阅读，不是四层必建目录

| 对象／身份 | 谁要回答什么 | 创建条件、放哪里与更新权 |
| --- | --- | --- |
| 项目／专题（macro，根 `0` 或等价现有入口） | 为什么做、范围／不做什么、已启动目标的状态／依赖／入口、未编号候选、全局风险、谁还需决定什么？ | 明确建系获权后建根；项目范围／全局风险或待决策、目标状态／跨目标依赖或入口实变才更新。未指定负责人／期限写未指定，绝不编造。 |
| 里程碑 `N`（meso，`N-0` 或等价摘要） | 一个可独立确认或终止的目标是什么，当前阶段、下一可评估节点、判据、证据／反证、阻碍与下一步是什么？ | 有权者确认目标开始且目录／文件获权才取不复用正整数 `N`；**节点是评估门槛，不是里程碑号或工作项**。一个 `N` 可有多个节点／方法。 |
| WBS 工作项 `N.W1`、`N.W1.1`…（meso 内的计划视图） | 交付成果分解到哪些工作包／必要行动，谁负责、依赖谁、何时有哪份可检查产物？ | 原目标确有分工、交付或后续追踪价值且授权后才建表；默认为同一个 `N-0` 的 WBS 节，复杂且另获授权时可用同目标 `N-WBS.md` 并互链。**不是新里程碑或 `N-1` 文件**。 |
| 独立执行／验证问题（micro，`N-1` 起或现有文档的可定位节） | 来源与当时判断、动作／环境、真实观察、反例、纠偏、复验如何形成？ | 已有获权且安全、值得回查的材料才新增；一篇可跨多轮／多工作项，一个工作项也可指多个安全证据。未发生的动作只列计划，不伪造过程。 |

**与普通项目计划工具的关系：**PVNW 是可读、可追溯的项目知识与执行记录 Skill，不替代团队使用的工单系统、预算或进度软件；现有工具可作 WBS 来源，用获权的链接／安全 ID 引用而非复制私有全量工单。项目目标、阶段、节点、工作项、执行证据五者不能仅靠目录层数互相推出。

## 命名与目录：先查旧规则，再采用新建基线

1. **定位：**先确认唯一、由有权者选定的项目根及分别允许创建／修改的路径。人的已选普通 Markdown 目录不会被另一个可用 Obsidian Vault 覆盖；已有文件、目录、编号、frontmatter 与目标项目的 `AGENTS.md`／规则优先。Obsidian 不要求插件／`.obsidian` 配置；无授权位置时不新建。
2. **仅在无既有约定且获权的全新项目中**，可选择以下稳定文件模式。`N` 用该项目未使用的下一个正整数；只有启动独立目标才分配，候选只在根保留文字。已分配的 `N` 即使中止、拆分、合并或失败都不回收；目录深度不表示 WBS 层级。`N-0` 是摘要，`N-1…` 是**按独立问题**而非任务轮次编号的过程篇；`N-WBS` 若存在是计划辅助页，不占过程号。同一文件的不同节或项目现有文件也可以承担职责。

   ```text
   <有权者选定的项目文档根>/
     0-项目总览.md                     # 范围、目标状态/依赖、候选、下一决定及入口
     1-恢复演练/
       1-0-当前判断.md                 # 目标/阶段/节点，默认 WBS 表，证据与下一步
       1-1-验证失败与纠偏.md           # 独立问题的来源、尝试、观察和反证
       1-WBS.md                       # 仅 WBS 很复杂且另获权时使用，须与 1-0 互链
   ```

3. **确定名字：**短标题描述目标或独立问题，不在文件名写身份、秘密、私人绝对路径或易泄露的业务摘要；避开 `.`／`..`、前后空白、斜线、反斜线、控制符、常见跨平台保留字符 `<>:"|?*` 及设备保留名，检查大小写与 Unicode 规范化后仍无同名／模糊撞名。若路径或内容碰撞，先报告并取已有安全名／经授权的新名，不能覆盖现存稿。前缀是稳定身份，显示标题可以随证据变；别为优先级／日程变动重排文件号。
4. **改名、拆并与迁移：**目录／文件 rename、move、删旧入口与修复其他文件入链是不同许可。先盘点入链、锚、附件、人工编辑，列旧→新映射、旧入口保留办法与恢复条件，分批验证新旧可达及反向入口；不随意改变稳定 `N`／WBS ID，不把旧判断悄悄改成新判断。缺恢复点或逆操作许可，不做破坏性改旧稿，见 [routes-and-lifecycle](routes-and-lifecycle.md) 和 [provenance-and-permissions](provenance-and-permissions.md)。

## WBS：分解交付而非制造文件

1. **建表门槛：**用户需要项目执行、拆解、依赖或交付跟踪，且有写权时，从里程碑目标与可检验产物拆成工作包，再按需拆出可执行工作项；简单目标只写“下一步”，无需空 WBS。未被批准或未开始的候选工作项不占号。工作项可以对应一个或多个节点；多个工作项合力证明一个节点。节点的判据先在 `N-0` 明确，不用“完成清单百分比”冒充证据。
2. **稳定身份：**在所属 `N` 内从 `N.W1`、`N.W2` 分配一级成果／工作包，子项从 `N.W1.1` 起递增；层级只表达父子成果关系，`N.W1.1` 不等于目录 `N-1` 或节点 1。已经发布／引用的号不复用、不按优先级重新编号；拆分、取消或更换方法时原项保留状态和“由新项接替”入口，新项用未用过的号。既有项目若已有稳定 WBS ID，优先沿用，不硬生成第二种号。
3. **最小可操作行：**`ID｜父项/交付物与验收物｜支持的节点及依赖｜行动者/确认人｜状态｜下一步｜证据或缺口`。行动者、期限或验收人未指定写“未指定”；重要依赖／风险要能回指工作项或外部安全来源。计划未执行写“尚无观察”；完成工作项须标可回查产物／观察（若需人验收，标待确认）；**工作项完成不等于节点判据通过、更不等于人的冻结**。
4. **最小合成例（不是运行记录）：**`1.W1` 恢复样本可读（依赖已获权的样本）；`1.W1.1` 校验样本，状态进行中，下一步比对校验和，证据可写成“验证失败与纠偏 → `1-1-验证失败与纠偏.md`”（*仅在该文件确实存在于目标项目且链接可达时才写成目标项目里的相对 Markdown 链接*）；`1.W2` 隔离恢复演练，依赖 `1.W1`，目前尚无观察。节点“隔离恢复可复现并经有权人判定”须分别核查校验与演练结果；一份日志显示复制成功不够。
5. **链接关系：**根到 `N-0`，摘要到 WBS 节／辅助页和相关微观证据，WBS 行回指证据或明确“缺”；微观篇回到 `N-0` 并标关联的 `N.W…`。若段落锚在目标渲染器未核实，先链接实际文件并给可搜索的稳定 ID／标题；不写无法核查的假锚。仅链接到安全可访问的依据，缺权限报告未闭合，不造空证据篇。

## 状态、触发与最小同步批次

| 事件 | 项目根 `0` | 目标摘要 `N-0` 与 WBS | 微观问题篇／节 | 禁止的跳步 |
| --- | --- | --- | --- | --- |
| 未启动候选 → 获确认启动 | 从未编号候选转为带稳定 `N` 的目标、入口／依赖实变时更新 | 建已获权的目标现状；有工作分解价值时才建 WBS，不预占工作号 | 只有真实安全过程／既有来源才引用或落篇 | 不给候选抢号、造空记录或自动建 Vault。 |
| 行动与新观察／纠偏 | 通常不动；仅项目范围／全局风险或待决策、目标状态／跨目标关系或导航实变才更新 | **采用过程篇→摘要链时，每次过程篇更新同一逻辑变更跟进摘要进展或入口**；工作项交付计划／依赖／行动者／状态／下一步／证据等实变就更新对应 WBS 行；结论仅真变时改 | 按真实先后追加安全来源、动作、观察与纠偏，保留旧实质判断 | 不在项目根复制聊天或只更新过程篇却声称摘要已同步。 |
| 阶段／节点复评、阻塞／暂停 | 仅项目范围／全局风险或待决策、目标状态／跨目标依赖实变时更新 | 记预期与实得、未达标原因、下一低成本验证，工作项阻塞／改派需归因与行动者 | 回指实际观察／反证；若无观察写缺口 | 工作项标完成不等于节点通过；不得从节点通过自动冻结。 |
| 目标成功、未成功、取消或继续 | 目标状态／关系或入口实变则更新，并保留旧号／新目标关系 | 保留出口、实际证据、可复用发现与终止理由；若继续同目标须记录重启原因／新阶段，若另立可独立终止目标须获确认并取新 `N` | 保留安全过程及失败／反证，新增纠正入口 | 不回收旧号、不静默将曾确认成果改成从未确认。 |
| 已确认成果后来失效 | 标当前效力与新入口，只有在已获权且全局状态实变时 | 旧判断及人的确认范围仍可查，显著标反证、当前失效与新判断待确认 | 追加反证和安全回查对象 | AI 不可自行重冻，敏感材料保留仍服从安全边界。 |

**状态词可映射到已有项目词汇，不要求迁库统一枚举：**候选（无号）／进行中／暂停或阻塞／达成／未达成／取消；WBS 项可为待做／进行中／阻塞／待验／完成／取消，记录证据和谁作判断。冻结是**人的明确确认及范围**，与“达成”正交；已冻结成果后来失效并非“探索未达成”。阶段、截止时间、负责人和百分比均不自动生成。工作项曾完成后发现反证，保留完成时依据，追加纠正与当前状态，不用覆盖历史。

**写入前→执行→验收（一个逻辑批次）：**若已有项目没有独立摘要而用单篇／其他系统，依现有约定维护可定位的目标现状，不强造摘要。先读既有状态和人的改动、核目标位置与内容安全，列本轮将涉及的过程篇、摘要、WBS、根及所有需要修的入链；逐一确认目录／创建／修改／移动／恢复／Git 和公开权限。若目标项目要求过程与摘要原子同步而摘要无权写，**在写微观前停下**；若项目允许异步且只获部分权限，写合法部分并显著报告未同步的上层，不声称当前地图完整。新增目录／索引中途失败也停止后续动作，复核原入口与新增残留；仅在获准逆操作时清理自身新增物，否则留下可定位待恢复清单，不擅删除。破坏性操作遵循更严格的逐批恢复点与授权回滚。最后从根→目标→WBS 工作项→安全证据逐跳核路径、锚／ID 与反向入口，在拟提交快照重新核对；回答人的原项目问题，而非只报告表格填了几行。
