# 项目管理合同：三层身份、清单体、更新与生命周期

1. **何时读取**：获权建系、分解／追踪里程碑与 WBS、维护工作包过程或改名迁移时；普通问答按 [decision-gates](decision-gates.md) 判断，不默认落盘。
2. **新建而非迁移授权**：项目已有编号、文件、工具和人的现行决定优先；本版不授权重命名旧项目。本次人的命名纠偏明确 micro 工作包与全过程合篇，**不同于** v0.4.0 分开的 `N.W1` 计划项和 `N-1` 问题篇。

## 三层对象与唯一身份

| 对象／身份 | 读者需要回答什么 | 承载与生效条件 |
| --- | --- | --- |
| 项目／专题（macro，根 `0` 或等价现有入口） | 项目出口、范围／不做什么、已启动里程碑的状态／依赖／入口、未编号候选、全局风险和下一决定者是什么？ | 获权建立项目根；项目范围／全局风险或待决策、目标状态／跨目标关系或导航实变才更新。未指定者如实写未指定。 |
| 里程碑 `N`（meso，`N.0` 或等价摘要） | 这个可独立确认或终止的目标处于什么阶段，下一可评估节点、判据、工作包依赖、证据／反证和下一步是什么？ | 有权者确认目标开始后分配未使用正整数 `N`；新建时摘要放在对应的 `N_<短名>/` 子目录内。节点是评估门槛，**不是**里程碑号或工作包。 |
| WBS 工作包 `N.1`、`N.2`、`N.3`…（micro） | 具体交付／任务包如何计划、执行、观察、失败、纠偏、复验，哪些是真实结果与未验证项？ | 在 `N` 的目录内，真实需要分解／追踪且有获权安全内容时为工作包分配稳定号；新建一包对应一篇 `N.1_<短名>.md`，**这篇内部承载整个执行过程**，不是另建一份与 WBS 脱节的独立问题日志。里程碑摘要只索引／概括包的状态与依赖。 |

1. **边界**：目标可有多个节点／方法／工作包；工作包完成不等于节点通过或人的冻结。`N.1` 同时是工作包身份和 micro 文件前缀，**不是**里程碑编号、小数计算、完成顺序或必建子目录。
2. **现有工具**：获权范围内引用安全 ID／入口，不复制私有全量工单，也不造平行冲突账本。

## 新建项目的命名、目录与旧版兼容

1. **先定位并获权**：确认人选定的唯一项目文档根、目录／文件创建及修改权。已选普通 Markdown 目录不因机器另有 Vault 而被替换；先只读查现有文件、编号、大小写／Unicode 规范化、frontmatter、链接和项目规则。无授权位置不建；现有合规结构不强制迁移。
2. **新建且没有更优的现成约定时按下例命名；本次人的新建命名基线不是 v0.4.0 的旧连字符模板**：根 `0_<name>.md`，目标子目录 `N_<dir name>/`，其中目标摘要 `N.0_<name>.md`、工作包记录 `N.1_<name>.md`、`N.2_<name>.md`…；对应英文 `<name>` 是短而安全的描述，不是要写尖括号。`N` 是稳定的正整数，`N.0` 只给这个目标的摘要，`N.1` 起只给该目标内**真实启动／确定需要追踪**的工作包；未启动的里程碑／未形成工作包的候选不抢号，已分配的号无论失败、取消、改计划都不复用。一个包内的多个步骤／验证轮次写在**同一篇**的嵌套有序清单中，别每轮生一篇。更细的行动可用该篇中的可定位条目，除非有权者另定身份，默认不增加 `N.1.1` 或 `N-WBS.md`。

   ```text
   <获权的项目文档根>/
     0_项目总览.md
     1_恢复演练/
       1.0_当前判断.md              # 目标、下一节点、工作包入口／依赖、证据缺口
       1.1_样本校验.md              # 工作包 1.1：计划→执行→观察→纠偏→复验
       1.2_隔离恢复.md              # 工作包 1.2：依赖 1.1，未执行部分标未验证
   ```

3. **碰撞与迁移**：显示标题可随证据修正，稳定前缀不因优先级／日程变化重排；短名避开秘密、身份、私人绝对路径、`.`／`..`、前后空白、斜杠／反斜杠／控制符、跨平台保留字符 `<>:"|?*` 与设备保留名。重命名、移动、合并、拆分及旧入链修复须分别授权：先只读盘点并列旧→新路径／ID 映射、历史人改和附件／锚／回退点；保留旧入口或获准修复全部入链，小批验证且具备获准逆操作才改旧资料。旧 `N-0`／`N-1` 和 `N.W1` **不等于**新 `N.0`／`N.1`：旧问题篇可跨工作包，须逐项核归属与内容，不能按数字批量替换或覆盖原判断。仅新增索引可较低风险过渡；不能证明完整迁移时保留现有结构并说明未闭合，见 [routes-and-lifecycle](routes-and-lifecycle.md)。

## micro 工作包：全过程 Markdown 清单体笔记

1. **写作适用范围**：整个 Skill bundle 的 Markdown 正文（入口与七份引用），以及本 Skill 获权新写的宏、中、微项目笔记，均以清单体承载主干；标题与简短提示仅作导航，局部必要表格／代码块不取代有序清单。旧项目已有写法优先，不因此擅自改写。
2. **身份与当前入口**：篇首用标题与有序 Markdown 清单写 `N.1`、所属 `N.0` 相对回链、交付／可检查验收物、支持的节点／依赖、行动者／确认人（未知写未指定）、状态、下一步及证据缺口。`N.0` 的工作包索引记录 ID、交付、依赖、状态和相对链接／缺口；这是 micro 当前状态的上层投影，不是另一套不同号的 WBS。状态可用待做／进行中／阻塞／待验／完成／取消；完成须有可读产物／观察，需人验收就标待确认。简单目标无需为了凑表而生成虚构包；若明确获权完整建系但只有既有安全依据，可让摘要直接指向依据并说明尚无工作包记录。
3. **整个执行过程留在这篇**：按真实时间或可核先后，在同一工作包内持续追加：原问题与安全来源（版本／节／安全 ID、限定与提出者）→当时计划、条件和依赖→真实动作／环境→实际观察、失败信号与反证→人的决定和 AI 推断分别署明→为何纠偏、前后变化→复验动作、结果、未验证及下一步。先记计划、未执行就写未执行；不能事后伪造现场笔记，也不能为了“一篇完整”保留原始敏感聊天、凭据或未获权的第三方材料。多个工作包依赖同一证据时，在各自篇中链接同一安全来源并说明它能／不能证明什么，不复制假证据；过程新增必须保留旧实质判断及后来纠偏。
4. **严格按 Markdown 清单体组织正文，不等于硬填七个空栏目**：正文以 `1. …` 的有序条目承载一个判断／动作／观察，因果、从属、先后用嵌套有序列表表达，子级缩进**每层四空格**而不是 Tab；区分编号排版与稳定的 `N.1` 工作包身份。只有局部确需在多个对象 × 稳定字段之间横向比较时，才插入 Markdown 管道表；**同一单元格中的多项要点就地用 `1. …<br>2. …` 编号**，不默认移到表外。格内是视觉编号，不宣称原生语义 `<ol>`，Obsidian 与可访问性须另测；若一维链已足够，不套全篇表格。资料不足时只写已知事实和缺口，不以空模板冒充全过程。此写法根据人的清单体取舍，参见 [note-modeling](note-modeling.md) 的合成排写与来源边界；不是强制五问／能力等级量表。
5. **合成缩例（非真实演练）**：`1.1_样本校验.md` 内按清单体书写；观察是**合成假设**，不可宣称本机实际发生：

    ```md
    # 1.1 样本校验

    1. **目标与回链**：校验恢复样本；依赖获权样本；[返回目标](1.0_当前判断.md)。
        1. **计划**：比较校验和；在尚未执行时标「未执行」。
        2. **合成来源与假设观察**：演练样本 v1；假设校验不一致。
        3. **拟议纠偏**：改查读取条件；复验尚未执行，不写成实际成功。
    ```

    1. `1.2_隔离恢复.md` 若尚未形成需留痕的包，可只在 `1.0` 列候选，不生成空篇；若已获权明确跟踪，则记“依赖 1.1，尚无隔离观察”，不把 1.1 的校验失败当 1.2 的完成证据。

## 生命周期与同步批次

| 事件 | 根 `0` | 目标摘要 `N.0` | 工作包 `N.1…` | 不得跳步 |
| --- | --- | --- | --- | --- |
| 目标候选获确认启动 | 候选转已启动时更新目标入口／关系 | 创建获权的目标摘要及可检验节点 | 有真实工作分解需要且获权才建包；仅计划无行动时写未执行 | 不给候选占号或造空过程。 |
| 包的行动、证据、依赖、行动者或下一步实变 | 只有项目范围／全局风险或待决策、目标状态／关系／导航实变才改 | **采用 micro→摘要链时，每次工作包篇更新，在同一逻辑变更跟进摘要进展或入口**；状态／依赖／证据／下一节点真变再改对应摘要内容 | 同篇按顺序追加清单体过程、更新包当前状态与链接 | 不只写 micro 却声称摘要已同步；不把聊天全贴根。 |
| 节点复评、阻塞／暂停或改派 | 仅跨目标或全局实变时改 | 判据与实得并列，明确缺口、下一验证与行动者 | 在相应包记原因、证据、变更及剩余步骤 | 不以完成包数替代节点证据。 |
| 目标达成／未达成／取消／继续 | 状态／依赖／入口实变时更新，保留旧号 | 保留出口、反证及原因；原目标继续记新阶段，新独立目标须另获确认、取新 `N` | 保留失败及可复用发现，取消的包不回收号 | 不静默擦除历史或自动冻结。 |
| 曾冻结成果失效 | 已获权且全局效力实变时给新入口 | 保留人的旧确认范围，显著标反证与当前待确认 | 追加可安全回查的反证与纠偏 | 冻结仅由人明确确认；AI 不得自行重冻。 |

1. **预检**：既有项目可用等价入口，不强迫改名；先读工作树及人的修改，列获权需写的 micro、`N.0`、`0` 与旧入链／附件。各层创建、修改、移动／删除、Git、公开和逆操作分别核权。
2. **受控写入**：要求 micro 与摘要原子同步但摘要无写权时，写前停下；允许异步且只获部分权限时，显著报告尚未同步的上层。中途失败停后续批次，列残留／坏链，无逆操作许可不擅删。
3. **验收与 Git 收尾**：在拟提交快照逐跳核 `0`→`N.0`→`N.1…`→安全证据与反向入口；无证据标缺口，不凭链接存在宣称节点成功。WBS 进度实变或里程碑节点推进／复评完成一个逻辑批次时，按 [provenance-and-permissions](provenance-and-permissions.md) 核本地提交授权与暂存快照；不逐行提交，不因尚未到下一里程碑而遗漏已完整的工作包批次。
