# 用笔记回答问题，而非装饰文档

## 从对象本质到可复用判断

1. 写之前指出原问题、为何要留痕、对象间的关键关系、使用者会据此做什么。若现有模板使原问题无法表达，提出有依据的替代模型，再用反例挑战；不要为套格式而删掉有解释力的证据。
2. 实事求是地把**来源材料**、**人的取舍**、**AI 推断／提案**、**亲自执行或观察结果**及**尚未验证**分开。用户未确认的具体文稿内容、效果、跨宿主默认触发，不得写成已批准或已测试。
3. 过程篇保留决定先后、影响判断的误解和纠偏；采用过程篇→摘要链时，当前摘要每次跟进进展／入口，结论与验证边界仅在实变时调整。不是逐字保存全部聊天，也不在事后伪装成实时记录。
4. 执行前、执行中有新的决定/反例时就记下来，不在完工后倒填“曾经研究过”。带回原任务的答案、行动和未解决项；只满足排版不等于知行合一。

## 从微观依据到中观现状、宏观导航

1. **微观过程：**用一个可独立理解的问题作阅读单位，标清原问题、来源、当时的判断／反对意见、操作观察与纠偏先后。不要机械保存每句话，也不因套层级凭空制造过程篇。
2. **中观现状：**把同一目标可用的判断、适用范围、来源入口、最新进展、反证与未验证项放在读者能定位的摘要；来源可以是获授权的既有材料，不要求强制先写 micro 文件。采用过程篇→目标摘要的项目中，每次过程增量都跟进摘要进展／入口；仅判断、状态或边界实变时才改对应当前结论，不静默覆盖已冻结的历史判断。
3. **宏观地图：**呈现多个目标的状态、关系、未启动候选和入口，帮助读者判断该读哪个目标；项目范围／全局风险或待决策、目标状态／关系／导航实变且有权限时才同步，不能把所有微观流水账搬到全局。普通咨询若没有多目标问题，就不为“凑体系”制造地图；**明确授权从零建立完整项目体系时，即便当前只有一个真实目标，也建有实际内容和目标入口的根导航**，为后续目标状态与关系留可读起点。一个既有文件的不同节也可承担多个阅读职责。
4. **上升检验：**每条概括能否回查到安全、可访问的证据或人的决定？缺失就注明未验证；区分“当年有人确认”与“目前仍成立”。例如合成的“备份比较”过程新增一次离线演练：若只推进同目标进度，就跟进目标摘要进展／入口而不改根；若另启动可独立验收的“恢复演练”目标且边界获确认，才在有权范围添加新目标及跨目标导航。每一层的写入和公开权限仍须单独检查。
5. **读者逐级走查：**获授权的完整体系可按 `0-项目总览.md`（目标状态、依赖与中观入口）→ `1-目标/1-0-当前判断.md`（目前阶段、可评估节点与微观入口）→ `1-目标/1-1-独立问题.md`（原始安全条目、反证、具体回查步骤）阅读，也能反向返回。文件名是示例而非通用强制模板；同文不同节可以承担职责。核查每跳具体相对链接／节锚，原始材料另存且可安全引用时可直链该来源，不强制造一个微观空壳。中观证据不足要标缺口，不以宏观表面齐整掩盖。

## 中观工作分解与微观执行之间的接缝

1. 如果恢复演练目标需要协调样本校验和隔离测试，中观摘要可列两个 `1.W…` 工作包：谁下一步做什么、依赖什么、交付物如何检查。`1.W1` 完成复制检查并不证明“可恢复”这一评估节点通过；另一工作包的真实隔离恢复观察才可能支持复评。具体 ID 与条目字段、改名规则、状态迁移见 [project-system](project-system.md)。
2. 微观依**独立问题与真实先后**组织，不依工作项多少切成日志碎片。同一个失败演练的问题篇能同时反证两个工作项，一项工作也可能跨几篇材料；用稳定工作项 ID 与可到达相对链接互指。计划表写“尚未执行／缺证据”，实际失败才追加来源和纠偏。总结让读者先见下一节点、阻碍和下一动作，再选择下钻过程；不要用漂亮表格替代问题答案。

## 微观清单的最小可回查单位（合成示例，非真实测试）

1. 用**一个独立问题**组织，而非一轮聊天一个文件；按真实时间／可验证先后追加。为每条影响判断的原始清单保留安全可引用的最小原文或准确释义、来源标识（文档／版本／节或获权的记录 ID）、上下文限定语、谁提出以及何时观察；若是用户转述第三方课程／数据，标二手整理，勿冒称课程原句或本机实测。
2. 将「原问题→原始安全条目与出处→尝试的条件／动作→观察与反例→人的决定／AI 推断→纠偏前后及原因→具体可再执行的回查对象和动作」排成可追的顺序；没有某一步就标未验证，不编造时间和证据。原文包含秘密时不为保真而复制，按 [provenance-and-permissions](provenance-and-permissions.md) 删减或不落盘。
3. 合成样本（无用户私料）：原问题「离线备份真的可恢复吗？」；安全原条目「方案 A：每晚复制（测试计划 v1 §2，尚未执行）」；第一次尝试仅检查复制日志，观察“成功”但**未做恢复**；AI 旧推断“可恢复”证据不足；后续一次隔离的恢复演练返回错误，记环境／输入与失败信号；修正为“复制曾成功，恢复未达标”，下一步让有权者批准再做隔离恢复并比对校验和。目标摘要仅报告进展、链接此处的失败证据，不写成“人的结论已冻结”。
4. 具体回查须给**可在授权范围找到**的路径＋节／安全 ID＋复验条件／命令（若适用）及观察标准；版本过期、链接不通或资料不可公开时标限制，不能给私有绝对路径充数。对记录中旧实质判断追加醒目纠偏与互链，不静默擦掉；若材料敏感，历史保留服从更高层安全要求。

## 按实际维度选局部结构

- 一维因果／从属关系，可用嵌套有序列表表达层级，不强造多列表格。
- 多维同时比较，可尝试局部 Markdown 管道表格，把同格多个判断写成 `1. …<br>2. …` 以便视觉定位。例如下表是**合成结构示意**，不是两项方案已测试或优劣定论：

  | 对象 | 可回查的测试条件 | 下一步 |
  | --- | --- | --- |
  | A | 1. 复制日志有记录<br>2. 恢复尚未验证 | 1. 先做隔离恢复<br>2. 比对校验和 |
  | B | 1. 尚无安全可引用日志<br>2. 别据此宣称失败 | 1. 先核实来源<br>2. 获权后再测试 |

  格内编号只得到**视觉编号**，不是语义 HTML `<ol>`；需要在目标渲染器核查复制、编辑和可访问性，不普遍强制。
- 表格若割裂论证，应换回段落或有序列表；“前后展示”并非自动意味着一个维度。
- 链接优先使用相对且可到达路径，引用外部来源时说明日期或版本；不得为了追踪而存储原始敏感对话、访问凭据或身份信息。

## 可检验的问题

记录完成后自己反问：后来的人能否看出原问题、为何采用该模型、证据在哪里、哪些是人的确认、哪些仅是推断、当前下一步能否执行？若不能，补上缺失链路；若材料不足，明确不确定而非编造。
