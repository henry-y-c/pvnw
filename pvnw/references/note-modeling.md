# 用笔记回答问题，而非装饰文档

## 从对象本质到可复用判断

1. 写之前指出原问题、为何要留痕、对象间的关键关系、使用者会据此做什么。若现有模板使原问题无法表达，提出有依据的替代模型，再用反例挑战；不要为套格式而删掉有解释力的证据。
2. 实事求是地把**来源材料**、**人的取舍**、**AI 推断／提案**、**亲自执行或观察结果**及**尚未验证**分开。用户未确认的具体文稿内容、效果、跨宿主默认触发，不得写成已批准或已测试。
3. 工作包篇保留整个执行过程的决定先后、影响判断的误解和纠偏；采用 micro→摘要链时，当前摘要每次跟进进展／入口，结论与验证边界仅在实变时调整。已获权包篇在主体研究前写真实问题、可检验计划及未执行状态；每个安全可观察步骤结束就追加做了什么、得到什么或为何失败，不能事后补写成实时记录。不是逐字保存全部聊天，也不为了搜索次数造多个包。
4. 执行前、执行中有新的决定／反例或实际动作时就记下来，不在完工后倒填“曾经研究过”。带回原任务的答案、行动和未解决项；只满足排版不等于知行合一。

## 从微观依据到中观现状、宏观导航

1. **微观工作包**：一个 `N.1` 是一个交付／任务包，同时承载它从计划、来源、执行观察到失败／纠偏／复验的全过程；原问题可在同包多轮出现，按先后保留，但不机械保存每句聊天或为凑层级造空篇。正文严格用 Markdown 清单体组织，见下节。
2. **中观现状**：把同一目标可用的判断、适用范围、工作包身份／依赖／入口、最新进展、反证与未验证项放在读者能定位的 `N.0` 摘要；来源可以是获授权的既有材料，不要求强制先写 micro 文件。采用工作包篇→目标摘要的项目中，每次过程增量都跟进摘要进展／入口；仅判断、状态或边界实变时才改对应当前结论，不静默覆盖已冻结的历史判断。
3. **宏观地图**：呈现多个目标的状态、关系、未启动候选和入口，帮助读者判断该读哪个目标；项目范围／全局风险或待决策、目标状态／关系／导航实变且有权限时才同步，不能把所有微观流水账搬到全局。直接可答的简单咨询不为“凑体系”制造地图；**明确授权从零建立完整项目体系或工作空间托管策略准许建系时，即便当前只有一个真实目标，也建有实际内容和目标入口的根导航**，为后续目标状态与关系留可读起点。一个既有文件的不同节也可承担多个阅读职责。
4. **上升检验**：每条概括能否回查到安全、可访问的证据或人的决定？缺失就注明未验证；区分“当年有人确认”与“目前仍成立”。例如合成的“备份比较”过程新增一次离线演练：若只推进同目标进度，就跟进目标摘要进展／入口而不改根；若另启动可独立验收的“恢复演练”目标且边界获确认，才在有权范围添加新目标及跨目标导航。每一层的写入和公开权限仍须单独检查。
5. **读者逐级走查**：获授权的新建体系可按 `0_项目总览.md`（目标状态、依赖与中观入口）→ `1_目标/1.0_当前判断.md`（阶段、节点和工作包索引）→ `1_目标/1.1_样本校验.md`（工作包的完整过程、安全条目、反证与复验）阅读，也能反向返回。已有项目命名优先，不强制迁移。核查每跳具体相对链接／节锚，若原始材料另存且可安全引用可直链，不强制造空 micro。中观证据不足标缺口。

## 中观工作包索引与 micro 全过程之间的接缝

1. 恢复演练目标需要协调样本校验和隔离恢复时，中观 `1.0` 索引两个工作包：`1.1` 对应 `1.1_样本校验.md`，`1.2` 对应 `1.2_隔离恢复.md`；标交付、依赖、状态及入口。`1.1` 复制／校验完成并不证明“可恢复”节点通过，`1.2` 的真实隔离观察才可能支持复评。具体 ID、改名和状态迁移见 [project-system](project-system.md)。
2. micro 按**工作包身份与真实先后**组织，同包多轮尝试写同篇而不是切成聊天日志；同一证据若影响两个包，分别以相对链接引用安全来源和可证明的范围，不能把一包的结果直接复制成另一包的结论。未执行写“尚未执行／缺证据”，实际失败才追加来源和纠偏；摘要让读者先见下一节点、阻碍和下一动作，再下钻过程。

## 全部 Skill Markdown 与 micro 清单体的写法（合成示例，非真实测试）

1. **全域规则**：本 Skill 的入口、按需引用、公开说明与获权新写笔记均按 Markdown 清单体组织：章节标题只作导航，正文的一维解释／条件／过程用一义一条的有序列表承载；依赖、因果和先后用**每层四空格**缩进的嵌套有序列表（不用 Tab）。不机械填五问、能力等级或没有事实的空条目；简短提示／表题和代码块为辅助，不取代主干清单。项目现有格式约定优先，不能借 Skill 擅改旧资料。
2. **加粗边界**：清单项标签统一写作 `**标签**：正文`，不要把中文冒号等标点放进 `**` 内再紧贴正文。行内强调也避免紧贴前后的汉字：需要时留空格或把标点放在强调之外；不要写不成对的星号。生成／修改获权 Markdown 后，在交付或拟提交前检查受影响文件的加粗、链接及局部表格；遇到原样显示的 `**` 先修正文法；能访问目标阅读器则抽查显示，否则标渲染未验证，不能仅凭源码静态检查声称各宿主都已正确渲染。旧项目的人写正文无修订权时只标问题，不借排版规则擅改。
3. **micro 单位**：一个工作包一个文件而非一轮聊天一个文件；在同篇按真实时间／可验证先后追加。为每条影响判断的原始清单保留安全可引用的最小原文或准确释义、来源标识（文档／版本／节或获权记录 ID）、上下文限定语、谁提出以及何时观察；用户转述第三方课程／数据标二手整理，勿冒称课程原句或本机实测。
4. **真实先后**：按「原问题→原始安全条目与出处→尝试条件／动作→观察与反例→人的决定／AI 推断→纠偏前后及原因→复验对象和动作」持续追加；没有某一步就标未验证，不编造时间和证据。原文包含秘密时按 [provenance-and-permissions](provenance-and-permissions.md) 删减或不落盘。
5. **合成样本（非运行结果）**：一个隔离恢复工作包的原问题是「离线备份真的可恢复吗？」；用嵌套 Markdown 清单记录来源与先后，不把不同阶段挤成一个长段：
    1. **原始安全条目**：「方案 A：每晚复制」（测试计划 v1 §2，尚未执行；合成来源）。
    2. **第一次尝试**：仅检查复制日志，观察“成功”但**未做恢复**；AI 旧推断“可恢复”证据不足。
    3. **后来观察与纠偏**：一次隔离恢复返回错误；记环境／输入与失败信号，修正为“复制曾成功，恢复未达标”。
    4. **下一步**：请有权者批准再做隔离恢复并比对校验和；未做前不写成人已确认。摘要只报进展并链接证据。
6. **复查定位**：给获权范围内可找的路径＋节／安全 ID＋复验条件／命令（如适用）与观察标准；版本过期、链接不通或资料不可公开时标限制。旧实质判断追加醒目纠偏与互链，不能静默擦掉；敏感材料服从安全例外。

## 按实际维度选局部结构

1. **一维链**：因果／从属用嵌套有序列表表达层级，不强造多列表格。
2. **局部多维**：多个对象 × 稳定字段同时比较时，用局部 Markdown 管道表格；同一格多个判断**就在格内**以 `1. …<br>2. …` 编号，不默认放到表外。下表是合成排版示意，非两方案实测：

    | 对象 | 可回查的测试条件 | 下一步 |
    | --- | --- | --- |
    | A | 1. 复制日志有记录<br>2. 恢复尚未验证 | 1. 先做隔离恢复<br>2. 比对校验和 |
    | B | 1. 尚无安全可引用日志<br>2. 别据此宣称失败 | 1. 先核实来源<br>2. 获权后再测试 |

    1. **技术边界**：格内编号是视觉编号，不是语义 HTML `<ol>`；渲染、编辑、复制与可访问性要在目标工具另测。
3. **回到主干**：表格若割裂论证，改回有序列表；前后展示用了两列，不代表笔记本身一定是二维。相对链接须可达，外部来源标日期／版本，不存敏感原始聊天、凭据或身份。

## 可检验的问题

1. **完成复查**：后来的人能否看出原问题、建模原因、证据、人的确认、AI 推断及可执行下一步？
2. **失败出口**：链路缺失就补；材料不足就明确不确定，不编造。
