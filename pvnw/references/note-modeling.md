# 用笔记回答问题，而非装饰文档

## 从对象本质到可复用判断

1. 写之前指出原问题、为何要留痕、对象间的关键关系、使用者会据此做什么。若现有模板使原问题无法表达，提出有依据的替代模型，再用反例挑战；不要为套格式而删掉有解释力的证据。
2. 实事求是地把**来源材料**、**人的取舍**、**AI 推断／提案**、**亲自执行或观察结果**及**尚未验证**分开。用户未确认的具体文稿内容、效果、跨宿主默认触发，不得写成已批准或已测试。
3. 过程篇保留决定先后、影响判断的误解和纠偏；当前摘要只同步真正改变的结论、验证边界和入口。不是逐字保存全部聊天，也不在事后伪装成实时记录。
4. 执行前、执行中有新的决定/反例时就记下来，不在完工后倒填“曾经研究过”。带回原任务的答案、行动和未解决项；只满足排版不等于知行合一。

## 按实际维度选局部结构

- 一维因果／从属关系，可用嵌套有序列表表达层级，不强造多列表格。
- 多维同时比较，可尝试局部 Markdown 管道表格，把同格多个判断写成 `1. …<br>2. …` 以便视觉定位。这个写法只得到**视觉编号**，不是语义 HTML `<ol>`；需要在目标渲染器核查复制、编辑和可访问性，不普遍强制。
- 表格若割裂论证，应换回段落或有序列表；“前后展示”并非自动意味着一个维度。
- 链接优先使用相对且可到达路径，引用外部来源时说明日期或版本；不得为了追踪而存储原始敏感对话、访问凭据或身份信息。

## 可检验的问题

记录完成后自己反问：后来的人能否看出原问题、为何采用该模型、证据在哪里、哪些是人的确认、哪些仅是推断、当前下一步能否执行？若不能，补上缺失链路；若材料不足，明确不确定而非编造。
