# 用笔记回答问题，而非装饰文档

## 从对象本质到可复用判断

1. 写之前指出原问题、为何要留痕、对象间的关键关系、使用者会据此做什么。若现有模板使原问题无法表达，提出有依据的替代模型，再用反例挑战；不要为套格式而删掉有解释力的证据。
2. 实事求是地把**来源材料**、**人的取舍**、**AI 推断／提案**、**亲自执行或观察结果**及**尚未验证**分开。用户未确认的具体文稿内容、效果、跨宿主默认触发，不得写成已批准或已测试。
3. 过程篇保留决定先后、影响判断的误解和纠偏；采用过程篇→摘要链时，当前摘要每次跟进进展／入口，结论与验证边界仅在实变时调整。不是逐字保存全部聊天，也不在事后伪装成实时记录。
4. 执行前、执行中有新的决定/反例时就记下来，不在完工后倒填“曾经研究过”。带回原任务的答案、行动和未解决项；只满足排版不等于知行合一。

## 从微观依据到中观现状、宏观导航

1. **微观过程：**用一个可独立理解的问题作阅读单位，标清原问题、来源、当时的判断／反对意见、操作观察与纠偏先后。不要机械保存每句话，也不因套层级凭空制造过程篇。
2. **中观现状：**把同一目标可用的判断、适用范围、来源入口、最新进展、反证与未验证项放在读者能定位的摘要；来源可以是获授权的既有材料，不要求强制先写 micro 文件。采用过程篇→目标摘要的项目中，每次过程增量都跟进摘要进展／入口；仅判断、状态或边界实变时才改对应当前结论，不静默覆盖已冻结的历史判断。
3. **宏观地图：**呈现多个目标的状态、关系、未启动候选和入口，帮助读者判断该读哪个目标；状态／关系／导航实变且有权限时才同步，不能把所有微观流水账搬到全局。若没有多目标问题，就不为“凑体系”制造地图。一个既有文件的不同节也可承担多个阅读职责。
4. **上升检验：**每条概括能否回查到安全、可访问的证据或人的决定？缺失就注明未验证；区分“当年有人确认”与“目前仍成立”。例如合成的“备份比较”过程新增一次离线演练：若只推进同目标进度，就跟进目标摘要进展／入口而不改根；若另启动可独立验收的“恢复演练”目标且边界获确认，才在有权范围添加新目标及跨目标导航。每一层的写入和公开权限仍须单独检查。

## 按实际维度选局部结构

- 一维因果／从属关系，可用嵌套有序列表表达层级，不强造多列表格。
- 多维同时比较，可尝试局部 Markdown 管道表格，把同格多个判断写成 `1. …<br>2. …` 以便视觉定位。这个写法只得到**视觉编号**，不是语义 HTML `<ol>`；需要在目标渲染器核查复制、编辑和可访问性，不普遍强制。
- 表格若割裂论证，应换回段落或有序列表；“前后展示”并非自动意味着一个维度。
- 链接优先使用相对且可到达路径，引用外部来源时说明日期或版本；不得为了追踪而存储原始敏感对话、访问凭据或身份信息。

## 可检验的问题

记录完成后自己反问：后来的人能否看出原问题、为何采用该模型、证据在哪里、哪些是人的确认、哪些仅是推断、当前下一步能否执行？若不能，补上缺失链路；若材料不足，明确不确定而非编造。
