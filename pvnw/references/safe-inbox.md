# 安全待归档线索：严格的例外，不是默认去向

本文件说明一个**可选规划方案**。目录名、ID 生成、冲突、保留期与具体 Git 可提交策略尚未通过真实项目验收；不要仅凭本示例创建目录或声称有持久队列。收件线索不是微观过程的草稿、中观摘要或宏观地图，不能借三层维护需要绕过任一层的写入权限。

## 同时满足才可考虑

1. 当前有**唯一、由有权者授权、适用于这一问题且安全可写的目标**；不是首次没有目标，也不是多个待选位置。
2. 本次资料对后续判断确有价值，而确切过程篇或编号尚待人判断。可以临时只留**最低限度非敏感线索**，不占正式里程碑编号。
3. 目标环境确实允许建这个收件位置、写相应内容；查看适用 `AGENTS.md`、权限、同步／公开边界后才执行。没有获授权收件目录就先问，不要“好心”自动创建。
4. 安全审查覆盖**真实内容、文件名、相对链接、提交信息及可能的 Git 历史**；不能靠字段白名单推断安全。任一关口不通过，停止持久化，继续原任务并说明原因。

## 最小候选字段（仍须逐值审查）

- 不含身份与语义的临时 ID，建立／更新时间；不要把用户、公司或路径编码进 ID。
- 一句非敏感目的和待确认原因，状态限“待确认／已关联”。只有正式记录确实存在后才补相对链接。
- 不保存原始聊天、凭据、账号、个人身份、完整绝对路径、敏感摘要或可反推身份的组合字段。禁止为了测试而复制真实私有语料。

没有统一的临时 ID 或期限算法时，不借口“先落盘再说”；先选择本任务可核查且符合目标约定的方式或暂不持久化。归属明确后，经授权把必要信息并入正式记录，并核查临时线索的保留或安全删除；不要静默清理他人数据。**公开仓库永不充当收件箱。**

反例：刚开始咨询、没有可写目标，即便线索很有价值也先请求有权者选位置；同时有两个似乎相关的专题，也不能随便在其中之一建收件目录。
