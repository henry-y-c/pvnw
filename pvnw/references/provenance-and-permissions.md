# 证据、权限、敏感信息与扩散

## 来源／验证四分法

| 性质 | 应怎么写 | 不可暗示 |
| --- | --- | --- |
| 人的明确决定 | 记录取舍、范围、时间和仍未解决的边界 | 没说过的文件正文也获批准 |
| 公开材料或仓库源码 | 标注链接、版本／读取日期、相关原句的准确含义 | 本机已照文档运行 |
| AI 提议和推断 | 给推理、可能失败的反例及低成本验法 | “常见做法”天然适用于所有人 |
| 本机实际测试 | 记录具体命令／输入、环境与观察结果，区分通过／失败／未运行 | 静态检查等于宿主实际默认启动或用户目标完成 |

从有证据的前提走到原任务出口：先找真实阻碍，再给可执行行动与结果；不能用漂亮的状态标签掩盖没解决的问题。

## 每类动作单独判权限

1. 读文件、写新文件、改旧稿、建目录／收件区、搬移或删除、Git 提交、远端公开、安装到宿主是不同的动作。实际项目的更高层规则与用户指令优先；本 Skill **不授予**任何一种权限。
2. 动文件前先看目标文件与工作树，辨识已有改动；不得借“更新笔记”覆盖人的修改。需要选择存储目标或公开策略时，请有权者确认，不靠路径猜测授权。
3. Git 会保留历史且可能公开：检查 staged 文件、路径、文本与 diff，特别是凭据、原始聊天、绝对私有路径、账号 ID、私有仓库地址和连同上下文可识别人的摘要。`.gitignore` 不能洗掉已入历史的敏感信息。无法安全隔离时不提交。
4. 未经许可不将研究笔记库、本地宿主配置或原目标的私有内容纳入可移植 Skill 仓库；“README 需要示例”也不能成为公开真实私有资料的理由。

## 完成时按实际情况报告

先回答用户原目标，然后列出确认事实、AI 假设、已执行验证、未执行验证、实际写入／未持久化范围；涉及 Git 再给实际提交和远端状态。不能只说“检查通过”，更不能因为某个仓库有 SKILL.md 就承诺客户端每次都会调用它。
