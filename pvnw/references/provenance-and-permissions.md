# 证据、权限、敏感信息与扩散

## 来源／验证四分法

| 性质 | 应怎么写 | 不可暗示 |
| --- | --- | --- |
| 人的明确决定 | 记录取舍、范围、时间和仍未解决的边界 | 没说过的文件正文也获批准 |
| 公开材料或仓库源码 | 标注链接、版本／读取日期、相关原句的准确含义 | 本机已照文档运行 |
| AI 提议和推断 | 给推理、可能失败的反例及低成本验法 | “常见做法”天然适用于所有人 |
| 本机实际测试 | 记录具体命令／输入、环境与观察结果，区分通过／失败／未运行 | 静态检查等于宿主实际默认启动或用户目标完成 |

1. **证据到答案**：先找真实阻碍，再给可执行行动与结果；状态标签不能掩盖未解决的问题。
2. **逐层概括**：从 micro 工作包到 meso 判断再到 macro 状态／关系，核来源是否安全可引、目前有效、反证及人的确认；“规划已完成”不能证明各层正文获批、冻结或已产生收益。

## 每类动作单独判权限

1. 读文件、写新文件、改旧稿、建目录／收件区、搬移或删除、Git 提交、远端公开、安装到宿主是不同的动作。操作系统层面的“路径可写”仅是技术能力，不证明人授权当前位置建 Vault；实际项目的更高层规则与用户指令优先；本 Skill **不授予**任何一种权限。
2. 动文件前先看目标文件与工作树，辨识已有改动；不得借“更新笔记”覆盖人的修改。微观过程、中观目标摘要与宏观专题地图可能各在不同目录或权限域；授权改其中一层不连带允许建新文件、改其他层或公开 Git。需要选择存储目标或公开策略时，请有权者确认，不靠路径猜测授权。持续维护或托管建系许可须能从当前有权者指令或可核实且适用的工作空间／项目规则看到目标位置、具体专题边界、文件／层级与创建／修改动作范围；有权者可在限定范围明确委托后续启动目标和新建目录／文件，但一次性建系许可、旧会话助手的自称或未经核实的会话摘要不能充当跨任务写权。即使有持续许可，本次明确“不记录”、范围外新建／搬删、敏感内容及工作树冲突仍分别挡住写入。只有授权可见时才在未来任务沿用；跨会话宿主未呈现旧决定就请人重申或建立受控项目规则，不能假装 Skill 自带记忆。
3. Git 会保留历史且可能公开：检查 staged 文件、路径、文本与 diff，特别是凭据、原始聊天、绝对私有路径、账号 ID、私有仓库地址和连同上下文可识别人的摘要。`.gitignore` 不能洗掉已入历史的敏感信息。无法安全隔离时不提交。
4. 未经许可不将研究笔记库、本地宿主配置或原目标的私有内容纳入可移植 Skill 仓库；“README 需要示例”也不能成为公开真实私有资料的理由。

## Git 收尾：完整进度批次，不是每次编辑一提交

1. **准入**：本 Skill 被宿主实际调用、目标已有可用 Git 仓库，且有权者在本任务明确允许本地 commit，或目标项目的适用规则明确授予此类文档的本地提交权时，才进入自动提交；有仓库、写权或个人偏好本身不构成提交许可。当前任务明确“不提交”优先于先前或项目级本地提交许可；仅明确“不推送”只限制 push，不阻止已有授权且安全的本地 commit。Git 安装、push／公开仍各需独立授权。无明确提交许可时，在检查点提出具体范围请有权者决定，不要默默跳过或擅自提交；明确禁止 commit 时只报告未提交，不再催促。
2. **进度检查点**：研究中每个获权且安全的可观察步骤都及时记到同一工作包篇并同步必要摘要，但不逐步／逐行提交。每完成一个有交付证据的 WBS 包、或出现有证据且需停下的受阻出口，核一次完整逻辑批次；WBS 状态、交付证据、阻塞、依赖或下一行动者实变时，同批先完成 micro 过程与获权 meso 进展／入口同步；里程碑节点推进、失败、复评或目标状态改变时，先完成获权摘要与条件性宏观入口。已有本地 Git 且获明确 commit 权时限范围提交，不自动 git init，不等到整个里程碑才提交；新建三层结构、获准旧库重构的单个可恢复批次或任务结束时累积的安全小修正也可组成完整批次，不逐行／逐文件提交。没有实际文档变更就没有文档提交。工作包完成不等于节点通过，不为等“节点成功”而积压已完整的 WBS 批次。
3. **批次与暂存预检**：动文件前看工作树与已有暂存；列本批次的已授权文件和必要入链，不覆盖人改。仅暂存可隔离的本批路径／差异；先检查 `git status`、暂存文件及删除、`git diff --cached --check`、暂存文本的敏感信息与 Markdown 加粗边界，并在拟提交快照验证相对链接、证据入口与必要 micro→meso 同步。已有暂存或同文件的旧改动无法安全隔离、凭据风险、失效链接、同步缺权、Git 不可用或检查失败时停止提交并报告，不用 `git add -A`、不替人清空暂存、不用跳过检查的办法强行提交。
4. **实际结果**：提交后核 commit id、包含文件和剩余工作树；无许可时说明拟提交范围与所需确认，禁令／阻断时说明具体原因和下一步。局部提交不等于任务成功、人的冻结或已 push；本 Skill 没有后台定时器／Git hook，不能保证没被宿主调用的任务自动进入检查点。

## 从零建系／旧库重构的具体授权边界

1. 有权者选定目标路径与允许的内容范围，**不等于**授予 `.obsidian` 配置、已有文件写／搬／删、祖先目录修改、Git commit、公开或宿主安装权限。先只读发现当前工作空间规则、已有获权 Vault／专题；已有适用 Vault 不另造，人的已选普通 Markdown 文件夹无需因另有 Vault 而改选。若没有适用 Vault，当前工作空间可核实的托管策略明确指定唯一建 Vault 位置，且逐项允许建目录、根／摘要／包文件及后续写入，就视为有权者预先选定的位置；在约定位置建 Obsidian 兼容 `.md` 文件夹和相对链接，不因安装 Obsidian 就自动建 `.obsidian`。无此策略、多个可能目标或位置冲突则请人选择；托管授权也不自动包含 Git commit 或已有文件搬删。
2. 旧库先只读盘点内容权属、人工编辑、历史冻结、相对链接／锚、附件、跨目录引用及同步／公开边界，再向有权者展示旧→新映射、预计改动和**可逆的**保留旧入口／快照方案。备份本身也可能泄密：选安全位置并取得相应许可，不生成未授权的副本。只有被明确批准的批次和动作才执行；对每批确认**可验证的恢复点及获准逆操作**，没有恢复权就不做破坏性搬移／覆盖／删除。不能用“宏观先行”推断可移动旧文或覆盖人的判断。
3. 每批先验证旧入口可读，再验证新的宏→中→微或安全来源路径、附件与反向引用；在**拟提交快照**与交付物中都检查链接与内容。如果当前树可用但提交快照缺一层，暂缓提交并报告；批次失败先停后续动作，按已授权步骤回滚本批并重新核查旧入口／附件／锚及残留新链接；不能回滚时停止并交付人工恢复清单。恢复点未证实可用、存在覆盖风险或链接修复不全，不启动破坏性迁移、也不宣称已完成。与目标项目要求同步的层级权限不齐时，按 [routes-and-lifecycle](routes-and-lifecycle.md) 的停机边界处理。项目根、里程碑摘要、WBS 工作项、微观篇以及受改名影响的入链可能属于不同权限域：依 [project-system](project-system.md) 先列本轮完整写入集合、逐项预检权属，再开始批次。即使仅新增索引／导航，中途失败也要核新增残留和失效链接；无获准逆操作／删除权时不自行清理。
4. 微观原始清单只摘录必要且获准的安全条目，附版本／安全 ID／节、观察条件和纠偏前后可查关系。凭据、身份、私有绝对路径或受限的整段聊天，即便“原文保真”也不进入笔记、收件箱、迁移备份或公开示例；引用权限不足或无法安全脱敏则报告不能留原文。二手课程整理和仓库源码、人在会话中决定、本机运行观察保持分离。

## 完成时按实际情况报告

1. **先答原目标**：列确认事实、AI 假设、已执行／未执行验证、实际写入／未持久化范围。
2. **Git 与宿主**：涉及 Git 再给实际提交和远端状态；不能只说“检查通过”，更不能因为仓库有 SKILL.md 就承诺客户端每次调用。
